# Архитектура

```text
src/
├─ app/                 # providers, маршрутизация, глобальная инициализация
├─ pages/               # композиция маршрутов без доменной логики
│  ├─ investor/
│  └─ team-lead/
├─ widgets/             # крупные повторно используемые блоки: AppShell, Sidebar, Topbar
├─ features/            # пользовательские сценарии и действия
│  ├─ investor/
│  │  ├─ dashboard/     # главная / обзор
│  │  ├─ offers/        # каталог и процесс оформления
│  │  ├─ portfolio/     # позиции, условия, договор и статусы
│  │  ├─ operations/    # пополнения, выплаты, выводы
│  │  ├─ reports/
│  │  └─ messages/
│  └─ team-lead/
│     ├─ dashboard/
│     ├─ offers/        # создание и публикация предложений
│     ├─ applications/  # рассмотрение и согласование
│     ├─ contracts/
│     ├─ portfolio/     # действующие позиции и покрытие
│     ├─ operations/
│     ├─ reports/
│     └─ messages/
├─ entities/            # модели и отображение Offer, Application, Contract, Portfolio, Operation, Report
└─ shared/
   ├─ api/              # API-клиент, query keys, transport
   ├─ config/           # env, feature flags, route-константы
   ├─ lib/              # форматирование и утилиты
   ├─ types/            # общие типы, включая роли
   └─ ui/               # базовые UI-компоненты
```

## Роли

`investor` проходит путь «предложение → оформление → договор → пополнение → портфель → операции / отчёты». Договор не является верхнеуровневым пунктом: он открывается в контексте оформления или позиции портфеля.

`team-lead` создаёт предложения, рассматривает обращения, согласовывает условия, подписывает договоры, наблюдает состояние позиций, обрабатывает операции и публикует отчётность.

## Граница ответственности

`features` описывает сценарий и UI конкретной роли. `entities` описывает общие бизнес-объекты. `shared` не зависит от `features`. Один feature может использовать entities и shared, но не должен импортировать другой feature напрямую.
